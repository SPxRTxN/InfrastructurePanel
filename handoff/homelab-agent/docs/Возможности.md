# homelab-agent — что делает и что умеет (версия 0.2.0)

Лёгкая программа на каждой машине лаборатории: собирает состояние машины и шлёт его в панель Homelab Dashboard,
по просьбе панели выполняет **только разрешённые на самой машине** действия, на Raspberry Pi — показывает
состояние на OLED-экране. Работает на Linux (Debian/Ubuntu/Raspberry Pi OS, Arch, Fedora, openSUSE — systemd) и
Windows 10/11/Server. ~30 МБ памяти, доли процента CPU при опросе раз в 10 с.

## 1. Что собирает (сборщики)
| Сборщик | Датчики | Где |
|---|---|---|
| `cpu` | загрузка %, load 1/5/15, частота | везде |
| `memory` | всего / занято / доступно (байты) | везде |
| `disks` | по каждому реальному разделу: размер / занято / свободно (как `df`, без tmpfs, снапов, повторов) | везде (Windows — `C:`, `D:` …) |
| `thermal` | температуры (`thermal_zone`, hwmon; на Pi — `thermal.cpu.temp`) | Linux |
| `uptime` | время работы | везде |
| `processes` | процесс запущен / CPU / память — по подстроке командной строки | везде |
| `systemd` | служба активна (1/0) | Linux |
| `checks` | TCP-порт и HTTP-адрес: доступен / задержка | везде |
| `command` | своя метрика: команда из конфига узла, из вывода — число | везде, **только на узле** |

По умолчанию включены cpu, memory, disks, thermal, uptime. Новый сборщик — один файл в `homelab_agent/collectors/`.

## 2. Связь с панелью
- Сам подключается по WebSocket (`wss://…/agent/ws`), открытых портов на машине не нужно.
- Может работать с **несколькими панелями** сразу (основная и на Pi) — независимо.
- Обрыв связи: выборки копятся в буфере и досылаются; переподключение с паузой.
- `ws://` без шифрования — только при явном `insecure = true`; `wss://` — всегда с проверкой сертификата.
- Токен — на узел, лежит в файле с правами 0600, в журнал не пишется.

## 3. Что можно делать с машиной из панели
| Возможность | Что | Включение на узле |
|---|---|---|
| **Действия восстановления** | кнопка в панели → команда из `[actions.*]` конфига узла (например, перезапустить nginx); лимит частоты, таймаут, без shell, вывод до 4 КБ; **автовосстановление** по правилу (`auto = { when = "...", for = 60 }`) | раздел `[actions.<имя>]` + строка sudo — только на узле |
| **Обновление агента** | выбрать версию в «Инфраструктура → Агенты» → скачивание с панели, проверка SHA-256, установка рядом, самотест на том же конфиге, переключение; не подключился за 2 мин — сторож возвращает прежнюю; откат кнопкой | `[update] enabled = true` (по умолчанию) |
| **Настройки** | интервал, сборщики (кроме `command`), дисплей, WoL, обновление — со страницы узла; агент проверяет и перезапускается | `[remote] config = true` (по умолчанию) |
| **Удаление** | удаление узла в панели (галочка) → агент удаляет себя с машины полностью; узел был офлайн — при следующем подключении | `[remote] uninstall = true` (по умолчанию) |
| **Wake-on-LAN** | разбудить ПК/сервер в той же сети по MAC (только широковещательный адрес) | `[wol] enabled = true` |
| **Терминал** | SSH-консоль и передача файлов из панели через агента: агент только пересылает байты на локальный sshd (loopback), входит и шифрует панель; лимиты сеансов и скорости | `[terminal] enabled = true` (только локально) |
| **VPN** | весь трафик машины через сервер из подписки (sing-box, при отказе — Xray), мимо — локальная сеть и панель; нет связи минуту — откат | `[vpn] enabled = true` + `install.sh --vpn` |

**Что из панели поменять нельзя** (только на самой машине): адреса панелей и токены, действия восстановления,
свои команды-сборщики, VPN, команда перезапуска агента. Поэтому даже при взломе панели нельзя выполнить
произвольную команду на машинах.

## 4. OLED-дисплей (Raspberry Pi)
SSD1306/SSD1315 128×64 по I2C (адрес 0x3C). Экраны по кругу (каждые 5 с): **сеть** (имя, IP), **здоровье**
(температура, загрузка, память, диск), **панели** (связь, сколько узлов онлайн, последняя тревога), **время работы**.
Против выгорания — сдвиг на 1–2 px и пониженная яркость ночью. Нет дисплея — агент работает дальше.

## 5. Установка и удаление
- С сервера на любые узлы: `sudo bash tools/push-agent.sh --install user@host …` (пароль sudo каждого узла).
- На узле вручную: Linux — `./start-agent` (токен в начале файла), Windows — `start-agent.ps1`.
- Всё в одной папке `/opt/homelab-agent` (`bin/` — root, `etc/` — конфиг и токены, `app/` — версии, `state/`,
  `systemd/`); снаружи — один файл sudo, ссылки на службы, служебный пользователь.
- Удаление: из панели (удалить узел) или `./uninstall-agent` — подробно в `УДАЛЕНИЕ.md`.

## 6. Для отладки
`python -m homelab_agent --once` — один сбор в JSON; `--check-config` — проверка конфига и прав на токены.
Настройки со всеми примерами — `agent.full.toml`. Протокол — `docs/Протокол.md`.
