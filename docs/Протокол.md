# Протокол агент ↔ панель (v1)

JSON-сообщения (текстовые фреймы) по WebSocket `wss://<панель>/agent/ws`. Каждая панель — независимое
соединение. Неизвестные поля и типы сообщений получатель игнорирует; поле `v` в `hello` — версия протокола.

## Агент → панель
```json
{"type": "hello", "v": 1, "node": "raspberry-pi", "token": "<токен узла>", "version": "0.1.0",
 "mac": "dc:a6:32:..", "ip": ["192.168.1.10"],
 "info": {"os": "Debian 12", "kernel": "6.6", "hostname": "pi", "cpu": "Cortex-A72", "threads": 4,
          "memory_kb": 948000, "boot_ts": 1761900000000},
 "sensors": [{"id": "thermal.cpu.temp", "kind": "temperature", "label": "CPU", "unit": "°C"}],
 "actions": [{"name": "restart_nginx", "label": "Перезапустить nginx"}]}

{"type": "sample", "ts": 1761900000000, "values": {"thermal.cpu.temp": 51.2, "memory.used": 412000000}}

{"type": "action_result", "id": "a-17", "name": "restart_nginx", "ok": true, "code": 0,
 "output": "…до 4 КБ…", "duration_ms": 812}

{"type": "event", "ts": 1761900000000, "level": "warning", "text": "nginx.service упал, автоперезапуск"}
```
- `kind`: строка `^[a-z][a-z0-9_]{0,23}$` (temperature, load, memory, disk, frequency, fan, power, state, latency, …).
- После обрыва агент шлёт буфер выборок (не больше N последних, настраивается) с исходными `ts`.

## Панель → агент
```json
{"type": "welcome", "interval_ms": 10000}
{"type": "error", "message": "bad token"}                 // и закрытие соединения
{"type": "action", "id": "a-17", "name": "restart_nginx"} // только имя из hello.actions, без аргументов
{"type": "summary", "online": 4, "total": 5, "alert": "Mini PC: диск / 91 %"}  // для экрана panels (опция)
```

## Возможности узла и VPN (2026-11-01)
- В `hello` агент передаёт `"features": [...]` — что владелец включил в конфиге узла (сейчас только `"vpn"` при
  `[vpn] enabled = true`). Панель шлёт сообщения возможности только узлам, которые её объявили.
- Панель → агент: `{"type": "vpn", "id": "v-N", "mode": "all", "server": {публичные поля}, "config": {sing-box}}`
  или `{"type": "vpn", "id": "v-N", "mode": "off"}`. Узел без `[vpn]` такие сообщения игнорирует.
- Агент проверяет конфиг (один inbound tun, разрешённые типы outbound, без `experimental`), добавляет адреса панелей в
  обход туннеля, `sing-box check`, применяет и `rollback_seconds` ждёт связи с панелью и интернетом; иначе — откат.
- Агент → панель: `{"type": "vpn_result", "id": "v-N", "ok": true|false, "detail": "…"}`.

## Wake-on-LAN (`"wol"`)
- Возможность `"wol"` в `features` — при `[wol] enabled = true` в конфиге узла (порт UDP 7 или 9, по умолчанию 9).
- Панель → агент: `{"type": "wol", "id": "w-N", "mac": "aa:bb:cc:dd:ee:ff", "broadcast": "255.255.255.255"}`.
  Узел без `[wol]` сообщение игнорирует. Агент проверяет MAC (строчные, через `:`) и что `broadcast` —
  широковещательный IPv4 (`…255`); иначе отказ.
- Агент отправляет magic packet (6 × 0xFF + 16 × MAC) по UDP и отвечает
  `{"type": "wol_result", "id": "w-N", "ok": true|false, "detail": "…"}`.
- Панель выбирает онлайн-узел с `"wol"` в `features` (по умолчанию первый; при нескольких — выбор в форме) и ждёт ответ ~8 с.

## Терминал: TCP-туннель к локальному sshd (`"tunnel"`)
- Возможность `"tunnel"` в `features` — только при `[terminal] enabled = true`; рядом в `hello` поле `"tunnel_max": N`
  (`max_sessions`). Агент лишь пересылает байты на один адрес из своего конфига (`[terminal] target`, строго loopback);
  SSH (вход, ключ хоста, PTY, SFTP) делает панель поверх туннеля. Адреса и команд в протоколе нет.
- Панель → агент: `{"type": "tunnel_open", "id": "t-N"}` (без адреса).
- Агент → панель: `{"type": "tunnel_opened", "id": "t-N", "ok": true}` или `"ok": false, "detail": "busy" | "disabled" | "connect failed"`
  (`busy` - достигнут `max_sessions`; `disabled` - на узле `[terminal]` выключен, отвечает и агент без feature новой версии).
- Данные в обе стороны: `{"type": "tunnel_data", "id": "t-N", "d": "<base64>"}`, кусок не больше 32 КБ (больше - сеанс закрывается).
- Закрытие любой стороной: `{"type": "tunnel_close", "id": "t-N", "reason": "…"}`; неизвестный `id` игнорируется.
  Причины агента: `closed by host`, `idle timeout`, `queue overflow`, `bad data`, `chunk too large`.
- Изоляция: сеансы - отдельные задачи; очередь панель → сокет до 256 КБ на сеанс (переполнение - закрытие); общий лимит
  скорости `rate_kbps` на все сеансы в обе стороны; `idle_timeout` секунд без трафика - закрытие; обрыв WebSocket к панели
  закрывает все сеансы этой панели; отправка в панель чередует `tunnel_*` и выборки, телеметрия не ждёт туннель.
  В логе агента - открыл/закрыл и число байт, содержимого нет. Раздел `[terminal]` панель менять не может.

## Обновление агента (`"update"`, 2026-11-01)
- Возможность `"update"` в `features` — при `[update] enabled = true` в конфиге узла. Панель шлёт `update` только таким узлам.
- Панель → агент: `{"type": "update", "id": "u-N", "version": "0.2.0", "url": "/agent/releases/0.2.0.tar.gz",
  "sha256": "<64 hex>"}`. Из `url` агент берёт только путь (должен быть `/agent/releases/<версия>.tar.gz`), адрес — тот же
  хост, что в `[[panel]] url` (`wss://` → `https://`, `ws://` → `http://`).
- Скачивание: `GET <панель>/agent/releases/<версия>.tar.gz` с заголовком `Authorization: Bearer <токен узла>`;
  без заголовка или с неверным токеном панель отвечает 401, нет такой версии — 404. Перенаправления агент не выполняет.
- Агент: SHA-256 → безопасная распаковка в `<prefix>/releases/<версия>/` → venv + `pip --only-binary=:all:` → самотест
  новой версии на том же конфиге (`--check-config`, `--once`; код 0) → symlink `current` (прежний — в `previous`) →
  ответ → перезапуск (`[update] restart_argv`). Версия, уже лежащая в `releases/`, ставится без скачивания (откат).
- Агент → панель: `{"type": "update_result", "id": "u-N", "ok": true|false, "detail": "…", "version": "0.2.0"}`.
  `ok: true` — версия проверена и включена, агент сейчас перезапустится.
- Подтверждение — новый `hello` с новой `version`. Не подключилась за `confirm_seconds` — сторож
  (`homelab-agent-guard.timer`, root) возвращает `previous` и перезапускает службу; агент вернётся со старой версией.
- Отметка для сторожа: после `welcome` агент пишет `/opt/homelab-agent/state/connected` («<версия> <время>»).
  `<prefix>` в путях выше — `/opt/homelab-agent/app` (раскладка «одна папка», см. README).

## Настройки и удаление из панели (`"config"`, `"uninstall"`, 2026-11-02)
- Возможности `"config"` и `"uninstall"` в `features` — агент объявляет их, если установлен в `/opt/homelab-agent`
  (конфиг лежит в `/opt/homelab-agent/etc`) и владелец не выключил: `[remote] config = false`, `uninstall = false`.
  Сообщение выключенной/неподдерживаемой возможности агент отклоняет ответом `ok: false`.
- Настройки.
  - Панель → `{"type": "config_get", "id": "c-N"}`
  - Агент → `{"type": "config", "id": "c-N", "managed": ["interval","collectors","display","wol","update"],
    "sections": {"interval": 10, "collectors": {...}, "display": {...}, "wol": {...}, "update": {...}},
    "local_only": ["panel","actions","vpn","collectors.command"]}` — в `sections` нет `collectors.command` и
    `update.restart_argv`.
  - Панель → `{"type": "config_set", "id": "c-N", "sections": {…только из managed…}}` — присланные разделы
    заменяют одноимённые целиком.
  - Агент отклоняет всё, что вне `managed`, а также `collectors.command` и `update.restart_argv` (это команды),
    проверяет итог (agent.toml + panel.toml + присланное) тем же разбором, что при старте, пишет `etc/panel.toml`
    атомарно (0600) и отвечает `{"type": "config_result", "id", "ok": true|false, "detail"}`; при `ok` перезапускается
    (`[update] restart_argv`, по умолчанию `sudo -n systemctl restart homelab-agent.service`).
  - Загрузка конфига: `agent.toml`, поверх — managed-разделы из `panel.toml`; нет файла — как раньше. Испорченный
    `panel.toml` агент игнорирует (журнал), а не падает.
- Удаление.
  - Панель → `{"type": "uninstall", "id": "x-N"}`
  - Агент → `{"type": "uninstall_result", "id", "ok": true, "detail"}` и затем запускает **фиксированную** команду
    `sudo -n /opt/homelab-agent/bin/uninstall-agent --from-panel` отдельным процессом (скрипт уходит в
    `systemd-run --no-block` и удаляет папку, юниты, sudoers и пользователя). Из сообщения агент ничего не исполняет.

## Токены
- Токен **на узел** (не на кластер): панель выдаёт его при добавлении узла и хранит только хеш (HMAC-SHA256 с перцем
  панели). Отзыв одного узла не задевает остальные.
- Узел с неизвестным именем по верному токену не создаётся — сначала добавить узел в панели.

## Что делает панель (реализуется в Homelab Dashboard, не в этом репозитории)
- Раздел «Узлы»: список агентов, онлайн/офлайн, последние значения, графики, кнопки действий из `hello.actions`
  (право `servers.edit`), журнал действий и событий.
- Узел привязывается к серверу и устройству топологии; статус узла красит граф.
- Хранение: последние значения + история с прореживанием (сутки — как есть, дальше минутные средние).
