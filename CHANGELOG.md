# История изменений

Формат: «## X.Y.Z — дата», новые версии сверху. Версия панели — `app/__init__.py`.

## 0.6.0 — 2026-11-05

- **VPN на узле: sing-box и Xray** (агент 0.5.x, миграции 0032–0033): узел пробует sing-box, затем Xray (xhttp — только
  Xray), не вышло — откат; отпечаток TLS на выбор; **журнал подключения** в плитке VPN и «Событиях».
- **Установка агента из панели**: команда для Linux и **Windows** (`irm … | iex`), по SSH кнопкой и **сразу при
  добавлении сервера**; ход установки одной строкой с полосой; галочка **«Свой Python»** (миграция 0034).
- **Страница сервера — вся информация** (сеть, интерфейсы с MAC, VPN, датчики, события, графики с зумом), узел — только
  настройки; плитки по две в колонку, сворачиваются со сводкой; плитки «добавить» с диалогом.
- **Настройки агента полями с подсказками** вместо JSON; консоль через агента включается из панели.
- **Консоль**: подключается сама, «Через агента / SSH напрямую», окно логина — только при отказе входа, загрузка файла
  в панели вкладок.
- **`cli settings-check [--fix]`** и проверка настроек при чтении; **`cli nodes-check`** — узлы и входы агентов.
- Исправлено: `deploy.sh build.` (точка из текста) тянул несуществующий образ.

- **SSH-консоль в браузере**: кнопка «Консоль» — терминал (xterm.js) по WebSocket, вход по ключу или паролю
  (не сохраняется). Новое право `servers.console` — администраторам (миграция 0023); одноразовый билет с CSRF,
  проверка Origin, закрытие по бездействию и при выходе. **Вкладки терминалов** — до 10 сеансов на пользователя.
- **Консоль и файлы через агента** (агент 0.3.0, `[terminal]` на узле): туннель к локальному sshd узла, лимиты
  сеансов и скорости задаёт агент; в консоли — выбор «напрямую / через агента».
- **Записи сеансов** (миграция 0026): только вывод терминала, «Настройки → Записи консоли» — проигрыватель,
  скачивание `.cast`, закрепление; режим всегда / по выбору / никогда, хранение 30 дней.
- **Сервер — сводка, узел — настройка**: страница сервера только показывает (с графиками датчиков узла), всё
  управление — «Настройки узла»: тип устройства (сервер / компьютер / другое, миграция 0027), подключение к ОС и к BMC,
  сервисы, удаление с окном подтверждения и выбором «удалить агента / оставить».
- **Настройки панели**: Оповещения, VPN и Архив — разделы настроек; «Серверы и сервисы» убран; интервалы и сроки
  хранения — в разделе «Интервалы и хранение». Отпечатки ключей хостов не показываются.
- **Сохранённые входы сервера** (ОС и BMC со своим адресом, пароль зашифрован) — выбор в консоли без ввода пароля;
  ссылка на веб-интерфейс BMC. Кнопка «Консоль» на странице узла.
- **Ключи хостов запоминаются сами** при первом подключении (accept-new), отдельно для адреса и порта — `ssh-keyscan`
  не нужен; смена ключа — отказ, сброс кнопкой. Касается и SSH-мониторинга (миграции 0024, 0025).
- **Вход вручную — командой ssh**: `ssh пользователь@адрес` или `ssh -p порт пользователь@адрес`, без `-p` — 22.
- **Передача файлов на сервер** по SFTP со страницы консоли: в `~/` вошедшего пользователя, прогресс, без замены
  по умолчанию, до 8 ГБ, журнал.
- Исправлено: в Docker любое SSH-подключение падало с «ошибка SSH (ValueError)» — у пользователя контейнера нет имени.
- Исправлено: новые иконки не попадали в `icons.svg` (пустые кнопки) — сборка сама берёт иконки из шаблонов, тест следит.
- Release: ручной запуск для уже отправленного тега (Actions → Release → Run workflow).
- Все пути установки — в `.env` (`PROJECT_DIR`, `DATA_DIR`, `BACKUP_DIR`, `GITHUB_REPO`); `CONTRIBUTING.md`, ветка `dev` для PR.

## 0.5.0 — 2026-11-02

Первая версия с релизами: у панели появился номер версии (виден внизу меню и в `/healthz`),
а по тегу `vX.Y.Z` на GitHub собираются образ и файлы для установки.

### Что есть в панели
- **Вход и права**: пароли argon2id, сессии, CSRF, блокировка перебора, группы с правами, журнал безопасности.
  Первый вход `admin` / `admin` с обязательной сменой пароля.
- **Главная, Инфраструктура**: серверы и сервисы, узлы с агентами, карта сети (серверы и устройства
  связаны), диски и память, графики за 24 часа, архив удалённого с историей.
- **Агенты** (`homelab-agent` 0.2.0): телеметрия в панель по WebSocket, разрешённые на узле действия
  восстановления, Wake-on-LAN, дисплей OLED. Обновление, откат и настройки агентов — из панели
  («Инфраструктура → Агенты», страница узла); удаление узла удаляет и агента на машине.
- **Карта сети**: связи протягиваются прямо на поле, порты по шаблонам устройств, Wi-Fi пунктиром,
  сегменты-рамки; действия по типу устройства (веб-интерфейс, Wake-on-LAN).
- **Обновление панели — из панели** («Настройки → Обновление»): всем остальным — «технические работы»,
  администратору — ход и лог; при неудаче откат. Выход после 30 минут бездействия.
- **Jira и Confluence**: канбан-доски, статьи в Markdown с историей версий, двусторонние связи;
  руководство пользователя встроено в Confluence панели.
- **Календарь**: события, повторы, напоминания в колокольчике и браузере, сроки задач.
- **Оповещения**: правила, тишина, колокольчик, Telegram и webhook, получатели по группам.
- **Бэкапы и перенос**: бэкапы по расписанию с проверкой восстановления, шифрование (SQLCipher, age),
  экспорт и импорт конфигурации `.hlconf`.
- **VPN**: подписка, сервер, трафик узла через VPN (со сторожем).
- **Установка**: Docker-образ (amd64 и arm64) и нативная установка службой systemd для Raspberry Pi.

### Как обновиться
- **Docker**: впервые — `sudo bash tools/deploy.sh build` (или `deploy.sh pull 0.5.0`): бэкап, выкладка,
  проверка, откат при сбое; заодно ставится служба обновления. Дальше — «Настройки → Обновление» в панели.
  Миграции БД применяются при старте, данные в томе сохраняются.
- **Нативная установка** (Raspberry Pi и др.): скачайте `homelab-dashboard-native-0.5.0.tar.gz` из
  релиза, проверьте `sha256sum -c SHA256SUMS`, распакуйте и выполните
  `sudo ./homelab-dashboard-0.5.0/deploy/native/install.sh --upgrade` — он сам сделает бэкап БД,
  заменит код, применит миграции и перезапустит службу.
- **Агент**: у него своя версия (0.2.0, свой `handoff/homelab-agent/CHANGELOG.md`). Узлы с агентом новой
  раскладки обновляются из панели кнопкой. Узлы со старым агентом — один раз
  `sudo bash tools/push-agent.sh --install user@host …`; новые — `homelab-agent-0.2.0.tar.gz` (Linux,
  `./start-agent`) или `.zip` (Windows, `start-agent.ps1`).
